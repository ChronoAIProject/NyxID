# Main publish gate reuse

The Publish Images workflow keeps the full CI gate as the safety boundary. On a
push to `main`, its small decision job finds the one pull request associated
with the commit, selects the newest completed successful `ci.yml` pull-request
run, and compares the pushed tree with the PR head tree. When the trees
match, individual successful jobs may be reused. The main and head commit
lookups must each return exactly that one merged PR, targeting this repository's
`main`, with `merge_commit_sha` equal to the pushed commit. The run's head
repository must equal the PR head repository. For a main push, the merge
commit's first parent must be an ancestor of the PR head and the PR head tree
must equal the pushed tree; no historical PR base SHA is trusted. Merged runs
often expose an empty `pull_requests` array, so the two exact-one commit
lookups are the authoritative base proof; when the array is present it is
validated as the same main PR.

The checked-out `ci.yml` blob is compared with the blob at the pushed commit.
The strict loader rejects duplicate keys, aliases, anchors, merge keys, tags,
non-string keys, and unsupported scalar types. Job identities are expanded
from local reusable workflows and simple matrix lists. Duplicate display names,
prefix overlaps, dynamic names, include/exclude matrices, missing or duplicate
API jobs, and unexpected children under a reusable prefix fail closed. Jobs
skipped by PR path filters, failed jobs, incomplete attempts, unsupported
matrices, and nested jobs without a complete successful set run on `main` under
`force-all`. Coverage threshold results are reusable; on a reused `main` gate,
the backend coverage baseline is produced by a separate non-blocking Publish
Images job.

For a version tag, the same decision may reuse the successful CI Gate from a
Publish Images run for the identical `main` commit. Workflow dispatches always
run the full gate. API errors, ambiguous pull requests, missing or in-progress
runs, and tree mismatches fail open to the full gate. The decision summary
records the source run, both tree hashes, and the reused job IDs; it never
trusts artifacts or text generated by a pull request. The proof assumes that
protected `main` is append-only (no force-push rewriting its ancestry), GitHub
commit-to-PR metadata is complete, and the Actions jobs API reports the latest
attempt's exact display names. It does not parse job logs; GitHub's jobs API
does not expose a checked-out merge SHA, so the first-parent/tree proof is the
checked-out-tree evidence.
