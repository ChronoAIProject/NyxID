# Web ingestion and safe assistant recovery

## Assessment

- #1878 is a valid integration/discoverability gap. NyxID already brokers Firecrawl (`api-firecrawl`) and exposes an authorized machine browser. The hosted overlay omits rendering/cache/sitemap controls, its metadata is stale, and the active NyxAgent instructions have no thin-content recovery procedure. The reported production extraction failure cannot be independently attributed to a particular provider from the issue alone. Implement in the existing connector/prompt layers, not a second browser or arbitrary backend URL fetcher.
- #1882 is a valid reproducible contract mismatch. The UI exposes Retry for every error, while `NyxAgentTransport.retry` requires both failed reply and user input in its local history page. Server-origin turns and page boundaries violate this requirement. The backend's existing retry lineage, upload restoration and canonical tool-digest fences are the correct authority to extend.

## Architecture and implementation

1. Web ingestion: extend the existing Firecrawl overlay with documented v2 rendering controls (bounded wait/timeout guidance), explicit cache freshness, sitemap discovery controls and structured content/provenance response fields. Preserve the supported overlay schema subset, normal catalog synchronization, grants, billing and proxy execution. Verify upstream field names/types against current official docs. Do not add credential-bearing headers/actions or create a new direct-fetch path. Keep read-only annotations accurate without widening unrelated operations.
2. Add a compact shared web-research procedure to the live NyxAgent prompt for NyxBot and specialists, respecting guest restrictions. Prefer ordinary fetch when useful; recognize title/metadata-only or blocked output as incomplete; discover an authorized rendered extractor, request readable body, retry rendering only within a small bound, map relevant URLs with common sitemap support, and use the existing machine browser only when authorized. Treat extracted content as untrusted data. Report source URL, actual extraction method and known cache/freshness metadata; never claim live/rendered provenance the provider did not establish. Never silently fall back from private authenticated content to a third-party public scraper. Update relevant connector skill/snapshot, seed metadata and docs consistently.
3. Safe recovery: define a service-owned, additive recovery projection for failed assistant replies, with stable eligibility/reason and original input lookup independent of history pagination. Share the eligibility logic with turn admission, revalidate within the existing claim transaction, and preserve ownership, role/origin/steering, active-turn, destroyed-agent, attachment-retention and retry-lineage checks. Use dedicated handler DTOs and Zod schemas. Never retry an automated/guest event as an owner request accidentally.
4. Frontend: render Retry only when the server says recovery is available; unknown/stale state cannot imply eligibility. Refresh/reconcile state before executing as needed. Offer a clear reason and safe recovery action without asking the user to retype; preserve original text/available attachments and completed-action fences. A recovery path must never silently replace a protected retry with an ordinary send. If evidence required for safe execution is missing or outcomes are ambiguous, offer a non-executing inspection/copy or review flow instead of automatic resubmission. Keep the existing design components and legacy transport behavior intact.
5. Preserve duplicate protection across repeated recoveries. Audit completed, unknown and digest-less actions and bounded ancestry; fail closed if evidence is incomplete rather than claiming exactly-once effects. Keep raw tool arguments/credentials out of diagnostics. Avoid N+1 history queries by batching page projections.

## Review decisions

- Retry availability and original-input lookup belong to the service layer. History and the focused recovery endpoint use dedicated response DTOs; turn admission independently revalidates before any execution.
- Each failed source is claimed once in the admission transaction. Persist lineage on both input and reply, inherit ancestor digests even when an intermediate retry made no calls, and reject incomplete or uncertain evidence. A full retained activity list is treated conservatively, including overlap with legacy writers.
- Tool activity must be recorded before dispatch. The append pipeline treats labels/digests as literal data and preserves unknown legacy counters. Guest provenance must survive both normal settlement and reclamation by a turn with a different audience.
- Recovery reads and frontend reconciliation are fenced against identity, deletion and history changes. A known admitted retry cannot be re-enabled by stale history. Review/copy/check actions never silently submit an ordinary request.
- Firecrawl additions retain the existing schema whitelist and provider extension support. Rendering limits are agent guidance, not schema-enforced limits. The unrelated agent-submit schema remains unchanged.
- Upgrade every serving backend replica before relying on the new retry safeguards; old binaries do not enforce source claims or evidence completeness. Legacy records cannot be safely backfilled from a truncated activity list.

## Product decision: defer native image search

Native GPT image search will not be added or enabled in this implementation. Image-search capability is deferred for discussion at a later date. NyxBot's current P0 is reliable, cost-effective discovery and execution of NyxID services, connections, and tools. Image generation is supported only through a dedicated NyxID-connected service using the normal authorization, execution, and usage-accounting paths.

The upstream NyxAgent runtime already supports provider-hosted text web search through its per-profile `webSearch` setting, but explicitly selects a text-only search tool. The local example enables search for chat/research; the Kubernetes template omits the setting, which defaults to false. The deployed policy remains unverified because runtime inspection requires authentication unavailable in this session. No runtime search configuration or OpenAI connector was changed.

This decision does not defer #1878's webpage-ingestion work or #1882's safe-recovery work. Recorded on Rona's issue: https://github.com/ChronoAIProject/NyxID/issues/1878#issuecomment-6182924440.
