# Verdict

This needs rework before merge. There is no BLOCKER, and the general transport-seam/catalog-resolution direction is sound, but four MAJOR defects make the implementation unsafe as-is: live blocks do not converge with reloaded history, the suffix-diff invariant is false for an accepted marker form, ordinary fenced content can mint a card, and OAuth completion does not converge the key-list state that drives the transcript card (`frontend/src/lib/assistant/aevatar-transport.ts:402`, `frontend/src/lib/assistant/connect-fence.ts:190`, `frontend/src/hooks/use-keys.ts:53`).

# Findings

1. **MAJOR - Live block order and IDs do not converge with history.** History indexes every text segment as `${messageId}-text-N` (`frontend/src/lib/assistant/aevatar-transport.ts:402`), while the live path pre-creates `${messageId}-text` (`frontend/src/lib/assistant/aevatar-transport.ts:1464`) and then skips the first text segment it encounters anywhere in the message (`frontend/src/lib/assistant/aevatar-transport.ts:2262`, `frontend/src/lib/assistant/aevatar-transport.ts:2283`). Exact input: ``"```nyxid:connect\n{\"catalog_slug\":\"api-github\"}\n```\nAfter"``. Reload produces `[m-connect-0, m-text-0("After")]`; live completion produces `[m-text("After"), m-connect-0]`, because `find(...)` treats the post-marker text as the leading text and the loop then skips it. For `"Before\n<marker>\nAfter"`, order is correct but live IDs are `m-text`, `m-connect-0`, `m-text-0`, whereas reload IDs are `m-text-0`, `m-connect-0`, `m-text-1`. A marker-only message has an extra empty `m-text` block live but only the card after reload. Stop also bypasses the splitter, so cancelling after the closing fence but before `TEXT_MESSAGE_END` leaves no live card until reload (`frontend/src/lib/assistant/aevatar-transport.ts:2462`). Use one deterministic projection/ID function for both paths, do not pre-assign a prose block before knowing the first segment, and add an end-to-end assertion that reducer state from live events exactly equals the history projection.

2. **MAJOR - `renderableText` is not monotonic for every marker the parser accepts, so raw marker text can leak and later suffixes can be sliced at the wrong offset.** The partial-line guard only checks `trailingLine.startsWith("`")` (`frontend/src/lib/assistant/connect-fence.ts:198`), but the parser trims the line before recognizing a marker (`frontend/src/lib/assistant/connect-fence.ts:118`, `frontend/src/lib/assistant/connect-fence.ts:127`). Exact deltas: first `"before\n  ```nyxid:conn"`, then `"ect\n{\"catalog_slug\":\"api-github\"}\n```\nafter"`. The first call returns `"before\n  ```nyxid:conn"`; after the second it returns `"before\nafter"`, which is not an extension. The transport then keeps the old `emittedText.length`, ignores the shrink, and eventually slices new safe text at a stale offset (`frontend/src/lib/assistant/aevatar-transport.ts:1493`). Reject non-column-zero marker openers consistently, or make partial detection use exactly the parser's opener grammar and track emitted output structurally rather than assuming length implies a common prefix.

3. **MAJOR - The ordinary-code-fence guard is not a correct fence state machine, so model/tool prose inside a valid code block can mint an actionable card.** `ANY_FENCE` recognizes only backtick fences and `FENCE_CLOSE` treats only a bare three-backtick line as a close (`frontend/src/lib/assistant/connect-fence.ts:29`, `frontend/src/lib/assistant/connect-fence.ts:31`). Exact input: `"~~~markdown\n```nyxid:connect\n{\"catalog_slug\":\"api-github\"}\n```\n~~~"` produces a connect segment even though the marker is inside a tilde fence. A four-backtick outer fence is also closed incorrectly by an inner three-backtick line (`frontend/src/lib/assistant/connect-fence.ts:120`), so a second marker still visually inside the outer fence is parsed. Four-space-indented marker examples are likewise parsed because every line is trimmed before matching (`frontend/src/lib/assistant/connect-fence.ts:118`). Assistant-role filtering does not distinguish Aevatar-appended text from LLM-authored assistant text (`frontend/src/lib/assistant/aevatar-transport.ts:444`). Track the opening delimiter character and length, accept only a matching close of at least that length, account for tilde/indented code blocks, and require the programmatic marker at column zero; Aevatar should also escape marker-shaped model output before appending its own marker.

4. **MAJOR - OAuth success updates only the detail query, so the dialog can say Connected while the transcript card remains Authorizing, and terminal rows continue polling forever.** `useKeyAuthorizationStatus` polls `['keys', keyId]` every two seconds whenever its caller says it is active (`frontend/src/hooks/use-keys.ts:66`), while `OAuthStep` keeps that flag true as long as `authorizationUrl` is non-null, including after `active` or `failed` (`frontend/src/components/dashboard/add-key-dialog.tsx:1454`). The connect card reads the separate `['keys']` list (`frontend/src/components/assistant/blocks/connect-card.tsx:38`) and derives Authorizing from its cached `pending_auth` row (`frontend/src/components/assistant/blocks/connect-card.tsx:85`). Exact scenario: the list refetches the newly-created pending row, the provider completes in a side-by-side tab without another focus event, and the detail poll returns `active`; the modal shows Connected but no code invalidates or patches `['keys']`, so the card stays Authorizing while `/keys/:id` keeps firing every two seconds. Stop the interval when data is terminal and invalidate or patch `['keys']` on both `active` and `failed` transitions.

5. **MINOR - An Authorizing card still offers an enabled Connect action that can create a second placeholder.** `authorizing` changes only the text/badge (`frontend/src/components/assistant/blocks/connect-card.tsx:85`); the action remains rendered whenever the service is not connected (`frontend/src/components/assistant/blocks/connect-card.tsx:136`). Exact scenario: `useKeys()` contains one inactive `pending_auth` GitHub key, the user clicks the still-visible Connect button, and the fresh `AddKeyDialog` path calls `POST /keys` for another GitHub placeholder (`frontend/src/components/dashboard/add-key-dialog.tsx:2618`). Disable/hide the action while authorization is pending, or reopen a resumable task tied to the existing key rather than starting a new connection.

6. **MINOR - Catalog query failures are conflated with a confirmed missing slug, while the button is actionable before catalog resolution.** Any exhausted error, including a 500, timeout, or 401, sets `unresolvableSlug` and tells the user the service is absent (`frontend/src/components/assistant/blocks/connect-card.tsx:45`, `frontend/src/components/assistant/blocks/connect-card.tsx:53`, `frontend/src/components/assistant/blocks/connect-card.tsx:95`). Conversely, while the query is pending, `unresolvableSlug` is false and the card enables Connect using the marker hint (`frontend/src/components/assistant/blocks/connect-card.tsx:47`, `frontend/src/components/assistant/blocks/connect-card.tsx:136`). Exact scenario: `/catalog/api-github` returns 500 three times; the card falsely says GitHub is not in the catalog and removes recovery. Treat only a 404 as missing, render a retryable error for other failures, and withhold the connect action until a catalog row has positively resolved.

7. **MINOR - Marker-free live streams are not byte-identical to the previous transport.** Every delta now passes through global trailing-whitespace removal (`frontend/src/lib/assistant/connect-fence.ts:203`, `frontend/src/lib/assistant/connect-fence.ts:214`) before emission (`frontend/src/lib/assistant/aevatar-transport.ts:1493`). Exact marker-free input: one delta `"Hello "` followed by `TEXT_MESSAGE_END`; previously the delta event carried `"Hello "`, now it carries `"Hello"` and the space appears only when `block.completed` replaces the block. A line beginning with `` `code` `` is withheld entirely until newline/end because it is treated as a possible marker prefix (`frontend/src/lib/assistant/connect-fence.ts:200`). Preserve the original delta path until an actual possible marker opener is encountered, buffering only the minimal ambiguous prefix.

# What's done well

User history is explicitly excluded from marker parsing (`frontend/src/lib/assistant/aevatar-transport.ts:444`), slugs are shape-checked and marker display strings are bounded (`frontend/src/lib/assistant/connect-fence.ts:33`, `frontend/src/lib/assistant/connect-fence.ts:73`, `frontend/src/lib/assistant/connect-fence.ts:76`), and marker scopes remain display-only (`frontend/src/lib/assistant/connect-fence.ts:43`). The card resolves modality/name from a NyxID catalog row (`frontend/src/components/assistant/blocks/connect-card.tsx:43`), while OAuth provider ID and submitted scopes come from that catalog-backed flow rather than marker text (`frontend/src/components/dashboard/add-key-dialog.tsx:1468`, `frontend/src/components/dashboard/add-key-dialog.tsx:1475`). The OAuth link uses `target="_blank"` with `rel="noopener noreferrer"` (`frontend/src/components/dashboard/add-key-dialog.tsx:1512`, `frontend/src/components/dashboard/add-key-dialog.tsx:1513`), the exact placeholder service ID is used for both initiation and polling (`frontend/src/components/dashboard/add-key-dialog.tsx:1485`, `frontend/src/components/dashboard/add-key-dialog.tsx:1488`), and device-code completion now invalidates the key list (`frontend/src/hooks/use-providers.ts:233`).
