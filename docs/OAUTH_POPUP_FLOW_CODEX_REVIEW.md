# Codex Adversarial Review — OAuth Embedded Flow Plan

Source: `codex exec` (gpt-5 class, high reasoning, read-only sandbox), 2026-08-04.
Target: `docs/OAUTH_POPUP_FLOW_PLAN.md` draft v1. Verbatim, unedited.

Claude verified against the repo and CONFIRMED findings 1, 2, 3 (partial), 5
(conditionally), 8, 13, 14, 24. See plan v2 §0 and §9 for disposition.

---

1. **[P1] §3.2 / §4.3, OAuth account binding and login-CSRF.** The callback explicitly accepts a missing NyxID session and relies only on the bearer-like OAuth state; it rejects only when a valid but different session happens to be present ([user_tokens.rs](backend/src/handlers/user_tokens.rs:460)). That permits credential-linking login-CSRF: an attacker logs into NyxID, initiates GitHub connect, and sends the resulting GitHub authorization URL to a victim who has no NyxID cookie; the victim authorizes their GitHub account, and the callback stores the victim’s GitHub token under the attacker’s NyxID account. Making `/oauth/complete` unauthenticated does not create this hole, but the plan institutionalizes the unsafe session assumption instead of separating browser popup flows, which should require the initiating NyxID session, from deliberate cross-device CLI flows, which need an explicit pairing/confirmation mechanism.

2. **[P1] §3.3 / §5 invariant 1, state is not single-use on all callback paths.** The claimed invariant is false. Only `handle_oauth_callback` atomically flips `consumed` ([user_token_service.rs](backend/src/services/user_token_service.rs:1528)); provider-denial handling merely peeks at the row, marks placeholders failed, and redirects without claiming or deleting it, while session-mismatch also returns before the claim ([user_tokens.rs](backend/src/handlers/user_tokens.rs:480)). Someone who obtains the state can replay `?error=access_denied&state=...` before the real callback, permanently mark the connection failed, and leave the state live; the later legitimate callback can obtain a provider token but cannot activate the now-terminal key.

3. **[P1] §3.3 / §6 error handling, “every error reaches `/oauth/complete`” is impossible with the proposed data.** Missing-code and missing-state branches redirect before looking up state; invalid or TTL-deleted state cannot reveal `display_mode`; provider errors currently return before retaining routing data; and a state can disappear between the handler’s peek and the service’s atomic claim ([user_tokens.rs](backend/src/handlers/user_tokens.rs:531)). For example, MongoDB deletes an expired popup state, GitHub returns a minute later, and the backend has no authenticated indicator that this was a popup flow, so it must use the legacy callback route or trust a new attacker-controlled query parameter. A distinct authenticated callback discriminator or a MACed/encrypted state envelope is required; an optional database field alone cannot deliver the promised routing.

4. **[P1] §3.3, the completion `key_id` does not exist at callback time.** The incoming `key_id` is normally a `UserService` ID, may alternatively be a `UserApiKey` ID, is resolved to `UserApiKey.connection_id`, and is then discarded ([user_tokens.rs](backend/src/handlers/user_tokens.rs:298)). `OAuthState` stores only `connection_id` ([oauth_state.rs](backend/src/models/oauth_state.rs:31)), and `OAuthCallbackOutcome` likewise returns the connection ID, not the service ID that `GET /keys/{id}` expects; legacy provider-grid and service-account flows have no key ID at all. The proposed redirect therefore cannot populate `key_id={connection key id}` consistently, and a receiver may refetch the wrong namespace or have no correlation value.

5. **[P1] §3.1 / §3.4, the popup cannot be opened synchronously using the current flows.** The plan’s prefetch claim is factually wrong: `AddKeyDialog` waits for `ensureKey()` and the initiate mutation before storing the authorization URL ([add-key-dialog.tsx](frontend/src/components/dashboard/add-key-dialog.tsx:1508)); provider-grid and service-account flows also await API calls before navigation; the wizard opens from an asynchronous effect after several awaits ([auth-flows.tsx](frontend/src/components/cli-wizard/auth-flows.tsx:979)). Safari and stricter Chromium configurations will treat the eventual `window.open` as lacking user activation and block it. Prefetching is not a free fix because it creates OAuth state, starts the ten-minute TTL, writes audit events, and caches a bearer-like authorization URL before the user elects to connect.

6. **[P1] §3.1 / §5 invariant 6, omitting `noopener` creates reverse-tabnabbing exposure.** “We do not use opener” is irrelevant: the newly opened provider page receives `window.opener` until COOP actually severs it, and not every configured OAuth provider is GitHub or serves effective COOP. A malicious or compromised provider configured through NyxID can execute `window.opener.location = "https://phishing.example/nyxid"` while presenting its consent page; the user returns to what appears to be the NyxID tab and enters credentials. The plan also removes `noreferrer`, restoring unnecessary origin referrer disclosure. This must be solved with a trusted same-origin launch interstitial or another design that severs the child’s opener before navigating to any provider, not by assuming provider headers protect NyxID.

7. **[P1] §2 / §3.1, `win.closed` is not reliable after COOP severance.** `closed` is cross-origin-readable while two contexts remain related, but a COOP browsing-context-group switch can make the opener’s old `WindowProxy` appear closed or inaccessible immediately even though the provider window remains visibly open; browser implementations also emit COOP access warnings around closed polling. The watcher can therefore report “window closed, retry?” as soon as GitHub loads, cause duplicate retries, and lose its focus/reuse control. The plan cannot simultaneously claim the handle is permanently severed and then treat that same handle as a reliable lifecycle oracle.

8. **[P1] §4.1 / §6, BroadcastChannel does not cross the relevant storage-partition boundary.** **No: a `BroadcastChannel` from a top-level NyxID popup does not, in partitioning browsers, communicate with the same-origin NyxID iframe embedded under a cross-site host.** BroadcastChannel membership is keyed by both origin and storage partition/top-level site: `nyxid.example` inside `aevatar.example` belongs to the Aevatar partition, while the top-level `nyxid.example` completion popup belongs to the NyxID partition. Same-site subdomains may share the same site key, but true cross-site Phase 2 does not. Consequently Phase 2 cannot “reuse Phase 1 unchanged”; instant completion disappears, and only an independently authenticated polling or explicit parent-mediated protocol can recover it.

9. **[P1] §3.1 / §6 concurrency, one fixed window name destroys independent flows.** `"nyxid_oauth"` is global to the relevant browsing-context group, while button disabling is only local to a component. Starting GitHub from one card and then Google from another navigates the first popup away mid-consent, abandons its state and placeholder, and presents the second provider in the same window; COOP severance may then prevent later name reuse and produce an additional popup anyway. Separate tabs, service-account administration, reconnects, and two simultaneously mounted components are not coordinated by this design.

10. **[P1] §3.1, named-window reuse adds a navigation-hijack surface.** An arbitrary unrelated browser tab cannot necessarily resolve the name across browsing-context groups, but any malicious page in the same opener-connected group, or a same-origin surface that can resolve the named context, can call `window.open("", "nyxid_oauth")`. It cannot read a cross-origin GitHub document, but it can retain a `WindowProxy`, monitor lifecycle, focus it, or navigate it to a credential-phishing page that inherits the small popup presentation. Fixed naming plus deliberate opener retention provides exactly the relationship needed for this clobbering attack.

11. **[P2] §3.2, the public completion route is a broadcast oracle with no per-attempt capability.** Any origin can induce a same-origin broadcast by opening `https://nyxid/.../oauth/complete?provider_status=success&key_id=...`; the loaded NyxID page itself becomes the same-origin sender, and any same-origin page or worker can publish directly to the global channel. If receivers strictly refetch and never transition UI from the message, this is limited to false wakeups, request amplification, misleading transient UI, and concurrency confusion, but that invariant is easy to violate later. A high-entropy, attempt-specific channel/correlation nonce bound into OAuth state is needed; object IDs and a global channel name are not authentication.

12. **[P1] §4.1, the parent `postMessage` protocol authenticates neither the flow nor the receiving window.** Pinning `targetOrigin` only limits where data is delivered; it does not prove to the host that the message came from its expected iframe or current connect attempt. The host-side receiver contract is absent, and checking only NyxID’s origin would let another NyxID window/frame report a forged success for a stale or different key. The host must verify `event.origin`, `event.source === iframe.contentWindow`, a one-time flow nonce, schema/version, and server-confirmed result; option (b) must also apply those checks to inbound bearer handoff, because checking only an allowlisted origin allows an allowlisted sibling frame to inject a token.

13. **[P1] §4.2, the nginx `/embed/` location does not serve the SPA correctly as described.** The current SPA works because `/` uses `try_files $uri /index.html` ([nginx.conf.template](frontend/nginx.conf.template:79)); an empty `/embed/` location tries a nonexistent filesystem path and returns 404. Adding the conventional fallback may internally redirect to `/index.html`, reselect `/`, and restore the server-level `X-Frame-Options: DENY`, defeating embedding. In addition, adding a location-level CSP stops inheritance of all server-level `add_header` directives on common nginx versions, so it can accidentally drop `nosniff` and `Referrer-Policy` along with XFO.

14. **[P1] §4.2, the claimed backend handler override cannot remove XFO.** The middleware respects a handler-provided CSP, but it unconditionally inserts `X-Frame-Options: DENY` afterward ([security_headers.rs](backend/src/mw/security_headers.rs:33)). A backend-rendered embed page with an allowlisting CSP remains blocked because XFO is still DENY. Any backend framing carve-out requires path/response-aware XFO behavior in middleware and tests for duplicate headers added by every reverse proxy/CDN layer.

15. **[P1] §4.2, a path-scoped CSP is not route-scoped inside an SPA.** `frame-ancestors` is evaluated when the HTML document loads, not on TanStack Router history changes. Once `/embed/connect` loads an allowed document, client-side navigation to login, keys, settings, approvals, or another sensitive route remains inside the already-approved framed document; the DENY header configured for those URLs is never fetched or evaluated. A malicious allowed host can clickjack any sensitive controls reachable through client navigation, especially the plan’s proposed embedded login state. The embed surface needs a separate constrained entry point/bundle or a hard frame-mode route boundary that cannot render the normal application.

16. **[P1] §4.1 / §4.3, the popup and iframe can authenticate as different NyxID users.** A cross-site iframe using a partitioned cookie or handed-off bearer can initiate for user A, but the top-level callback popup sends NyxID’s unpartitioned first-party `SameSite=Lax` cookie; that cookie may identify user B. The existing callback then rejects the valid flow as a session mismatch and marks A’s placeholder failed, while a missing/expired top-level cookie causes the opposite problem from finding 1 and accepts state alone. “Top-level means first-party, therefore callback works identically” ignores identity continuity across the partition boundary.

17. **[P1] §4.1, iframe popup permissions are unspecified and routinely break the flow.** External hosts commonly sandbox authentication iframes. Without `allow-popups`, the provider cannot open; with `allow-popups` but without `allow-popups-to-escape-sandbox`, the GitHub window inherits sandbox restrictions and may be unable to navigate, submit forms, download, or execute required scripts. Even without an explicit sandbox, browsers can apply stricter popup heuristics to third-party frames. The host integration contract must state required sandbox and permissions attributes and the security consequences of granting them.

18. **[P1] §6, expiry and retry semantics are wrong.** The state expires exactly ten minutes after initiation ([user_token_service.rs](backend/src/services/user_token_service.rs:709)), and lazy reconciliation treats an expired state as absent even before MongoDB physically deletes it ([user_api_key_service.rs](backend/src/services/user_api_key_service.rs:726)). A user delayed by GitHub login, MFA, organization approval, or account recovery can cross ten minutes while the dialog poll marks the key terminally failed; the later callback cannot reactivate a failed key. “Retry?” is not enough: retry must create a fresh state, atomically reset or replace the correct placeholder, invalidate the old attempt, and avoid the documented placeholder-before-state reconciliation race.

19. **[P1] §3.4 / §8, the service-account migration is absent from the backend design.** The service-account frontend calls a distinct POST hook, and `admin_sa_providers::initiate_oauth_for_sa` invokes the service directly with a fixed redirect path and no `display_mode` query ([admin_sa_providers.rs](backend/src/handlers/admin_sa_providers.rs:210)). Changing only `handlers/user_tokens.rs` cannot put SA flows into popup mode. Adding a field to the Rust struct also requires updating every `OAuthState` constructor, including device-code creation and tests; serde defaults help old BSON documents, not Rust compilation.

20. **[P2] §3.2, `key_id` and `message` in the URL have unaddressed privacy and retention consequences.** The completion URL is recorded in browser history, frontend/CDN access logs, crash reports, screenshots, and potentially pageview telemetry; same-origin asset requests can include a full same-origin Referer under the current policy. `key_id` is an account-scoped object identifier, and session-mismatch messages can contain masked email addresses. The completion page should use an opaque one-time attempt handle and fixed error codes, scrub the URL with `history.replaceState` immediately, disable telemetry/pageview capture for this route, and set an explicit no-referrer/no-store policy.

21. **[P2] §4.2, the allowlist format and trust model are underspecified.** CSP `frame-ancestors` expects a space-separated source list, while the proposed environment variable is comma-separated; blindly interpolating it produces invalid host-source tokens. Scheme and port are significant, `https://*.example.com` does not cover the apex and authorizes every matching subdomain, wildcard subdomains inherit takeover risk, `"null"` origins from sandboxed/file contexts must never be accepted, and every ancestor in a nested frame chain must match. Exact normalized origins should be parsed and validated at startup, then rendered safely rather than inserted as an unchecked nginx string.

22. **[P1] §6 mobile behavior, the promised contained flow does not exist on iOS Safari.** Popup dimensions and popup chrome hints are ignored; the “popup” often becomes a full browser tab, an installed PWA may be suspended while Safari owns the provider flow, BroadcastChannel/storage may not bridge the PWA/browser boundary, and `window.close()` may be refused or may not restore the original app. Polling resumes only after the user manually returns. The proposed fallback text leaves the user in the completion tab with no reliable return action, so Phase 1 does not meet its central UX objective on a major supported platform.

23. **[P2] §4.3, the CORS “hard blocker” is confused with iframe embedding.** The checked-in API client uses same-origin `/api/v1` URLs ([api-client.ts](frontend/src/lib/api-client.ts:5)); requests made by the NyxID iframe are therefore same-origin with NyxID, regardless of the parent’s origin, and CORS is not consulted. `Access-Control-Allow-Origin: *` plus credentials is a real problem only where JavaScript performs a credentialed cross-origin fetch. Treating it as the universal Phase 2 blocker risks fixing the wrong layer while leaving cookie partitioning, popup identity divergence, and BroadcastChannel partitioning unresolved.

24. **[P2] §3.2 router assumptions, `/providers/callback` is not actually a session-free precedent.** The cited exemption only bypasses the non-admin provider redirect; the route is still nested under `dashboardLayout`, whose `beforeLoad` sends unauthenticated users to login ([router.tsx](frontend/src/router.tsx:318)). `/oauth/complete` must be a root child with a minimal boot path. Reusing the full app boot can still run auth checks, telemetry initialization, chunk loading, and global error handling before the close attempt, undermining the claim that it has no session dependency.

**MISSING**

- A browser-popup account-binding policy that closes the credential-linking login-CSRF hole while preserving intentional CLI/cross-device authorization.
- A cryptographically random per-attempt completion nonce, distinct from `key_id`, bound into state and checked by every receiver.
- Atomic claim/delete semantics for denial, malformed, session-mismatch, expiry, cancellation, and success callbacks.
- A durable mapping from OAuth state to the exact `UserService`/`UserApiKey`, provider, owner, surface, and attempt generation.
- A global concurrency policy: unique window names or an explicit single-flow lock across components and tabs.
- A secure same-origin launch interstitial that preserves popup-blocker detection while severing opener before provider navigation.
- A cancel endpoint and defined retry transaction that cleans state and safely replaces or resets placeholders.
- A partition-aware Phase 2 completion channel; cross-site iframe polling must authenticate independently because BroadcastChannel will not bridge it.
- A separate embed entry point or enforced frame-mode route confinement so normal SPA routes cannot become frameable via client navigation.
- A complete host receiver specification covering `event.origin`, `event.source`, nonce, schema/version, replay, timeout, and server verification.
- Required iframe `sandbox`, `allow`, referrer-policy, and popup-escape attributes.
- Exact CSP origin parsing, nginx SPA serving mechanics, header inheritance handling, CDN/Cloudflare duplicate-header checks, and deployed-header tests.
- A threat model for compromised allowlisted hosts and wildcard/subdomain takeover.
- URL/history/referrer/telemetry handling for completion identifiers and errors.
- Mobile Safari, installed-PWA, popup-as-tab, manual-return, accessibility, focus restoration, and screen-reader behavior.
- Real browser tests with COOP responses and storage partitioning; mocked `window.closed` and BroadcastChannel unit tests cannot validate either behavior.
- Service-account endpoint changes, device-code constructor updates, every `OAuthState` initializer, and compile/test fallout from the new field.
- A decision on whether the completion message is merely a wakeup or a host-visible security result; the current plan claims both depending on the section.

**Overall verdict: reject the plan as written; Phase 1 has a credential-linking CSRF hole and unsafe popup lifecycle assumptions, while Phase 2’s principal completion channel is broken by storage partitioning and its framing carve-out does not actually confine framing to the embed route.**
