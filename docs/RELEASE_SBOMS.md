# SBOMs of shipped artifacts

The artifact gates produce CycloneDX 1.6 from finished artifacts. A source lockfile is an input to the build and to retained JavaScript membership verification; it cannot substitute for a binary, archive or image inventory. `security/publication-policy.json` defines the complete official publication set. The gates reject missing, duplicate, extra or mismatched subjects, changed source identity, broken dependency references and changed evidence bytes.

For each final stripped CLI executable, the locked artifact inspector parses the retained build identity and cargo-auditable section without running the executable. Pinned Syft independently catalogs that same file and must agree on the entire runtime package inventory. The binary SBOM retains the compiled graph, marks build dependencies explicitly and records reviewed vendored ancestry. Stable Cargo metadata can conservatively include dependencies whose emitted bytes cannot be attributed individually; the SBOM states that limitation. The embedded wizard requires both the exact bytes in the executable and its retained rendered JS/CSS membership, verified against a fresh, integrity-locked, hook-free frontend installation.

The CLI archive SBOM has the archive's SHA-256 as its subject and includes the binary graph and every planned archive member by digest. Archive traversal, links, duplicate members, unexpected files, architecture and GNU ABI mismatches fail inspection. Publication closure reopens every archive and compares its binary/member composition with the validated binary and archive SBOMs. It also rehashes all other planned release files, including the source archive, installers, checksums and credential manifest. `release-sboms.json` binds the complete subject set and the exact SBOM files. Release hosting replays that closure before its first upload and again against the final GitHub Release upload directory.

Image SBOM generation reads the exact OCI layout imported from the saved, vulnerability-scanned final image. Syft's default squashed scope describes the final filesystem, rather than discarded builder layers. The catalog's raw manifest and config bytes, manifest digest, image ID, architecture and tool version must agree with the staged subject. Scanning the Docker archive directly is deliberately avoided here: its synthetic manifest can differ from the exact OCI manifest published by regctl. The raw Syft catalog is retained alongside the converted inventory; conversion must retain every package, detected OS identity and cataloged file.

Each application executable is also extracted from the same immutable image ID, checked for ABI/build identity and independently cataloged. Its runtime inventory must equal the image catalog's inventory at the exact executable path. Backend credential pages and frontend assets are extracted from the final filesystem and verified for exact manifest/fingerprint/source identity, file closure and rendered composition. The frontend and credential SBOMs retain actual bundled package membership and every final asset hash. These child graphs are included in the platform SBOM whose subject is the actual OCI platform manifest digest.

Each multiarchitecture index gets its own SBOM. Its exact manifest bytes must reference the verified amd64 and arm64 platform manifests, and its SBOM contains both complete platform graphs. OCI subject validation checks the index/config/platform relationship. The complete-set gate requires all ten platform manifests and all five indices specified by the publication plan. Index assembly publishes by digest; real tags are promoted only after the complete-set gate passes, and the promotion helper independently replays the full closure before applying tags.

PR and weekly Artifact Packaging jobs generate and replay this evidence with read-only repository permissions. They retain workflow artifacts for review and never attach evidence to a registry or GitHub Release. The Release workflow alone attaches final binary/archive/credential SBOMs to its published release. Publish Images attaches a CycloneDX OCI referrer to each verified platform manifest and index using the pinned regctl. Missing or invalid SBOM evidence blocks the first platform registry copy, index publication or tag promotion, as applicable. Signing and trusted producer verification are separate mandatory release controls described in the release integrity documentation.

Private hosted images have an operator build boundary. `scripts/build-local-image.py` requires identity, final-image vulnerability and SBOM checks before applying a tag. It records the mandatory SBOM command/result in the retained receipt and keeps the complete bundle under `scanned-image/sbom`. The real public desktop stage exercises this wrapper on PRs. The final hosted stage additionally requires the private CMA build context and passes the same checks on the operator's Docker engine; PR CI does not fetch private patch bytes. A deployment digest must come from a successful wrapper receipt. Raw Docker builds do not qualify for deployment.

Local policy verification needs Python 3.9+, the hash-locked validator requirements and the pinned Syft/regctl binaries. Run `sh scripts/setup-sbom-tools.sh /tmp/nyxid-sbom-tools`, bootstrap regctl into its `bin`, then run `scripts/test-sbom-evidence.py` with `SYFT_BIN` and `REGCTL_BIN` pointing there. `scripts/test-sbom-workflows.py` needs the separately hash-locked build requirements. Real image builds/extraction and all four finished CLI archives are exercised by PR CI; no registry writes, repository secrets or OIDC are required for those jobs.
